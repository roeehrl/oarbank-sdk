<Aside type="caution" title="Not released yet">
  Oarbank itself (the coordinator and the node agents) has no public release yet: there are no installers or
  downloads. They arrive with the first public release. Until then, the installation steps below are a preview of how
  setup works, and file names and details may change. The source is public: the core is at
  [roeehrl/oarbank](https://github.com/roeehrl/oarbank) and the module SDK at [roeehrl/oarbank-sdk](https://github.com/roeehrl/oarbank-sdk).
</Aside>

## What you can do today

- **Learn how it works.** [How Oarbank works](/oarbank/concepts/how-oarbank-works) explains the coordinator, nodes,
  join codes, modules, certification, sandboxing, host protection, signing and coordinator moves.
- **Check your computers.** [Requirements](/oarbank/operate/requirements) lists what the coordinator and each node
  need on macOS, Linux and Windows, and what the network needs.
- **Read the core's source.** The coordinator, console, agent and launcher are source-available at
  [roeehrl/oarbank](https://github.com/roeehrl/oarbank). To try them before the release, you can build the packages yourself:
  [docs/install.md](https://github.com/roeehrl/oarbank/blob/main/docs/install.md) in that repository lists the build scripts and the install
  steps.
- **Build a module.** The module SDK (`oarbank-sdk`, Apache-2.0) is open source on
  [GitHub](https://github.com/roeehrl/oarbank-sdk). Install it from source (it is not on PyPI yet) and follow
  [Build a module in a day](/oarbank/build/tutorial), which builds a complete module step by step. See
  [Install the module SDK](#install-the-module-sdk) below.
- **Read the contracts.** The [specification](/oarbank/spec) describes everything a module can rely on, and the
  [JSON Schemas](/oarbank/reference/schemas) are published as files you can validate against.

## Install the module SDK

You need Python 3.12 or newer, on macOS, Linux or Windows. Install the SDK from its repository into your
environment:

```sh
uv pip install "git+https://github.com/roeehrl/oarbank-sdk"   # or: pip install "git+https://github.com/roeehrl/oarbank-sdk"
oarbank-sdk --help
```

To work with the reference module and the examples, clone the repository instead and check the toy module with the
conformance kit:

```sh
git clone https://github.com/roeehrl/oarbank-sdk
cd oarbank-sdk
uv sync --group dev
uv run oarbank-sdk conform examples/toy   # must end with "0 failed"
```

The conformance kit runs your module's runner as this computer's platform would, so you can build and test a module
before Oarbank itself is released.

## What installation will look like

A fleet is one **coordinator** and any number of **nodes**. The coordinator runs on macOS, Linux or Windows and can
also be a node itself. Every node, whatever its operating system, reaches the coordinator on one address and port; see
[Requirements](/oarbank/operate/requirements).

<Steps>

1. **Install the coordinator** on a Mac, a Linux machine or a Windows machine that stays on, and tell it the address
   nodes will use to reach it. It runs as a background service: LaunchAgents on macOS, systemd user units on Linux,
   Windows services on Windows.

2. **Create your console account** on the coordinator. You sign in to the console with a password and a TOTP code
   from your authenticator app:

   ```sh
   oarbank account create alice --role admin --password
   ```

   The console answers only on the coordinator itself (`http://127.0.0.1:7400`) until you put it behind a TLS proxy
   for a name you control.

3. **Make a join code for each node.** A join code names the coordinator's addresses, pins its certificate
   authority and approves the node when it is used. It works once.

   ```sh
   oarbank join-code --label build-box
   ```

4. **Install the node package** with its join code.

   <Tabs syncKey="os">
     <TabItem label="macOS" icon="apple">
       Put the join code where the installer looks, then install the package (by hand or through MDM):

       ```sh
       sudo mkdir -p /Library/Oarbank/etc
       echo 'OB1-…' | sudo tee /Library/Oarbank/etc/join-code >/dev/null
       sudo installer -pkg oarbank-agent-<version>-macos.pkg -target /
       ```

       The node runs for the user who is logged in. To run it as a system service that starts at boot, under its
       own `_oarbank` account, create an empty `/Library/Oarbank/etc/system` file before installing.
     </TabItem>
     <TabItem label="Linux" icon="linux">
       Put the join code where the package looks, then install the `.deb` (or the `.rpm` with `dnf`):

       ```sh
       sudo install -d /etc/oarbank
       echo 'OB1-…' | sudo tee /etc/oarbank/join-code >/dev/null
       sudo apt install ./oarbank-agent_<version>_amd64.deb
       ```

       The package creates an `oarbank` account and a systemd service whose jobs run in their own cgroups.
     </TabItem>
     <TabItem label="Windows" icon="seti:windows">
       Install the MSI with the join code, from an elevated prompt:

       ```powershell
       msiexec /i oarbank-agent-<version>-windows-x64.msi /qn JOINCODE=OB1-…
       ```

       The MSI installs the agent as a Windows service and a helper service that enforces each job's network
       allowlist. Use the `arm64` MSI on ARM64 PCs.
     </TabItem>
   </Tabs>

   The installer reads the join code and deletes it. The node enrolls with a key it generates and keeps, then
   installs its release, runs each module's doctor and golden jobs, and starts taking work.

5. **Add modules.** Oarbank ships no job module of its own: each job type is a module, delivered as a bundle. You
   install a bundle, approve what its sandbox may reach, and enable it:

   ```sh
   oarbank module install <bundle>.mfb
   oarbank module approve <name>@<version>
   oarbank module enable <name>@<version>
   ```

</Steps>
