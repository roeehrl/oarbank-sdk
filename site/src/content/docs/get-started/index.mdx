## Download

The current release is **Oarbank 2.5.0**, with module SDK 1.5.0. Every file and its checksums are on the
[release page](https://github.com/roeehrl/oarbank/releases/tag/v2.5.0). First check that your computers meet the [Requirements](/oarbank/operate/requirements).

| For | File |
|---|---|
| A Mac node with Apple silicon | [`oarbank-agent-2.5.0-macos-arm64.pkg`](https://github.com/roeehrl/oarbank/releases/download/v2.5.0/oarbank-agent-2.5.0-macos-arm64.pkg) |
| An Intel Mac node | [`oarbank-agent-2.5.0-macos-x86_64.pkg`](https://github.com/roeehrl/oarbank/releases/download/v2.5.0/oarbank-agent-2.5.0-macos-x86_64.pkg) |
| A Linux node (Debian, Ubuntu) | `oarbank-agent_2.5.0_amd64.deb`, `oarbank-agent_2.5.0_arm64.deb` |
| A Linux node (Fedora, RHEL) | `oarbank-agent-2.5.0-1.x86_64.rpm`, `oarbank-agent-2.5.0-1.aarch64.rpm` |
| A Windows node | `oarbank-agent-2.5.0-windows-x64.msi`, `oarbank-agent-2.5.0-windows-arm64.msi` |
| The coordinator | `oarbank-coordinator-2.5.0-<platform>.tar.gz` for `darwin-arm64`, `linux-amd64`, `linux-arm64`, `windows-amd64` or `windows-arm64`, and its installer, `install-oarbankd.sh` (macOS, Linux) or `install-oarbankd.ps1` (Windows) |

The macOS packages are signed with Developer ID and notarized by Apple. The Windows installers are not code-signed
yet: Windows SmartScreen may ask you to confirm before running one you downloaded with a browser.

## Set up a fleet

A fleet is one **coordinator** and any number of **nodes**. The coordinator runs on macOS, Linux or Windows and can
also be a node itself. Every node, whatever its operating system, reaches the coordinator on one address and port; see
[Requirements](/oarbank/operate/requirements).

<Steps>

1. **Install the coordinator** on a computer that stays on, and tell it the address nodes will use to reach it. It
   runs as background services: LaunchAgents on macOS, systemd user units on Linux, Windows services on Windows.

   <Tabs syncKey="os">
     <TabItem label="macOS" icon="apple">
       ```sh
       bash install-oarbankd.sh --build oarbank-coordinator-2.5.0-darwin-arm64.tar.gz --agent-bind <address>
       ```
     </TabItem>
     <TabItem label="Linux" icon="linux">
       ```sh
       bash install-oarbankd.sh --build oarbank-coordinator-2.5.0-linux-amd64.tar.gz --agent-bind <address>
       loginctl enable-linger    # once, so the coordinator starts at boot without a login
       ```
     </TabItem>
     <TabItem label="Windows" icon="seti:windows">
       In an elevated PowerShell:

       ```powershell
       .\install-oarbankd.ps1 -Build oarbank-coordinator-2.5.0-windows-amd64.tar.gz -AgentBind <address>
       ```
     </TabItem>
   </Tabs>

   `<address>` is where nodes reach this computer: its LAN, VPN or tailnet address. When it finishes, the installer
   prints the full path of the `oarbank` command it installed: use that path for `oarbank` in the next two steps, or
   add its folder to your `PATH`. On Windows, run them in an elevated prompt.

2. **Create your console account** on the coordinator. You sign in to the console with a password and a TOTP code
   from your authenticator app:

   ```sh
   oarbank account create alice --role admin --password
   ```

   The console answers only on the coordinator itself (`http://127.0.0.1:7400`) until you put it behind a TLS proxy
   for a name you control.

3. **Make a join code for each node.** A join code names the coordinator's addresses, pins its certificate
   authority and approves the node when it is used. It works once.

   ```sh
   oarbank join-code --label build-box
   ```

4. **Install the node package** with its join code.

   <Tabs syncKey="os">
     <TabItem label="macOS" icon="apple">
       Put the join code where the installer looks, then install the package for your Mac's chip (by hand or
       through MDM):

       ```sh
       sudo mkdir -p /Library/Oarbank/etc
       echo 'OB1-…' | sudo tee /Library/Oarbank/etc/join-code >/dev/null
       sudo installer -pkg oarbank-agent-2.5.0-macos-arm64.pkg -target /    # an Intel Mac: oarbank-agent-2.5.0-macos-x86_64.pkg
       ```

       The node runs for the user who is logged in. To run it as a system service that starts at boot, under its
       own `_oarbank` account, create an empty `/Library/Oarbank/etc/system` file before installing.
     </TabItem>
     <TabItem label="Linux" icon="linux">
       Put the join code where the package looks, then install the `.deb` (or the `.rpm` with `dnf`):

       ```sh
       sudo install -d /etc/oarbank
       echo 'OB1-…' | sudo tee /etc/oarbank/join-code >/dev/null
       sudo apt install ./oarbank-agent_2.5.0_amd64.deb
       ```

       The package creates an `oarbank` account and a systemd service whose jobs run in their own cgroups.
     </TabItem>
     <TabItem label="Windows" icon="seti:windows">
       Install the MSI with the join code, from an elevated prompt:

       ```powershell
       msiexec /i oarbank-agent-2.5.0-windows-x64.msi /qn JOINCODE=OB1-…
       ```

       The MSI installs the agent as a Windows service and a helper service that enforces each job's network
       allowlist. Use the `arm64` MSI on ARM64 PCs. Add `CONTAINERS=1` for modules that run containers (WSL
       containers; see [Requirements](/oarbank/operate/requirements)).
     </TabItem>
   </Tabs>

   The installer reads the join code and deletes it. The node enrolls with a key it generates and keeps, then
   installs its release, runs each module's doctor and golden jobs, and starts taking work.

   The coordinator's download holds only the coordinator: for the coordinator's computer to run jobs too, install the
   node package on it the same way, with a join code of its own. Every installer runs unattended, so you can also
   push it with your own SSH, MDM or configuration tool; the coordinator never connects to nodes itself.

5. **Add modules.** Oarbank ships no job module of its own: each job type is a module, delivered as a bundle. You
   install a bundle, approve what its sandbox may reach, and enable it:

   ```sh
   oarbank module install <bundle>.mfb
   oarbank module approve <name>@<version>
   oarbank module enable <name>@<version>
   ```

</Steps>

The full install guide, with system scope, updates, uninstalling and moving the coordinator, is
[docs/install.md](https://github.com/roeehrl/oarbank/blob/v2.5.0/docs/install.md) in the core's repository.

## Install the module SDK

To build your own job types, install the module SDK (`oarbank-sdk`, Apache-2.0). You need Python 3.12 or newer, on
macOS, Linux or Windows. It is not on PyPI yet; install it from its repository:

```sh
uv pip install "git+https://github.com/roeehrl/oarbank-sdk@v1.5.0"   # or: pip install "git+https://github.com/roeehrl/oarbank-sdk@v1.5.0"
oarbank-sdk --help
```

To work with the reference module and the examples, clone the repository instead and check the toy module with the
conformance kit:

```sh
git clone https://github.com/roeehrl/oarbank-sdk
cd oarbank-sdk
uv sync --group dev
uv run oarbank-sdk conform examples/toy   # must end with "0 failed"
```

The conformance kit runs your module's runner as each platform would, so you can test a module before you install it
on a fleet. [Build a module in a day](/oarbank/build/tutorial) builds a complete module step by step.
