## Set up a fleet

A fleet is one **coordinator** and any number of **nodes**. The coordinator runs on macOS, Linux or Windows and can
also be a node itself. Every node, whatever its operating system, reaches the coordinator on one address and port; see
[Requirements](/oarbank/operate/requirements).

<Steps>

1. **Install the coordinator package** for its operating system and processor. It installs the software without configuring or enrolling the fleet.

2. **Open the setup application:** **Oarbank Coordinator** in Applications on macOS or the application menu on Linux (`oarbank-setup` also works), or **Oarbank Coordinator** in Windows Start. Click the menu bar or tray icon and choose **Open web app**. A Linux desktop without a tray host shows these controls in a small window. Launch the companion as your ordinary user; Windows asks for administrator permission only when opening unfinished setup.

   Select a LAN or tailnet IP assigned to this computer that the nodes can reach. Enter your administrator name and password (at least 12 characters), confirm the password, and submit. This configures the services and creates the account. Scan the displayed QR code with your authenticator app and verify its six-digit code. The wizard creates and pins primary and backup owner signing keys; copy the backup key to secure offline storage. When setup finishes, it opens the console.

   The console stays local at `http://127.0.0.1:7400` unless you configure remote access. On macOS the coordinator runs while its user is logged in; Linux uses systemd user services, and Windows uses system services. See [Requirements](/oarbank/operate/requirements) for boot behavior and privileges.

   If you close the wizard before verification, choose **Open web app** again. The saved address and administrator name are shown; enter your original password to continue. Existing accounts and signing keys are preserved. Completed setup opens the normal console login.

   The menu also shows coordinator status and **Preferences…**. **Start automatically at sign-in** is optional and launches the companion quietly for your account. **Quit Oarbank Coordinator** closes the menu app while leaving coordinator services running. On Windows, Startup Apps can also disable automatic startup; on macOS, Login Items manages it.

3. **Make a join code for each node.** In the console, open **Fleet**, enter the computer's name, and choose **Join code for a new machine…**. Copy the displayed code. It names the coordinator's address, pins its certificate authority, approves one node and works once.

4. **Install the node package** with its join code.

   <Tabs syncKey="os">
     <TabItem label="macOS" icon="apple">
       Put the join code where the installer looks, then install the package for your Mac's chip (by hand or
       through MDM):

       ```sh
       sudo mkdir -p /Library/Oarbank/etc
       echo 'OB1-…' | sudo tee /Library/Oarbank/etc/join-code >/dev/null
       sudo installer -pkg oarbank-agent-2.7.0-macos-arm64.pkg -target /    # an Intel Mac: oarbank-agent-2.7.0-macos-x86_64.pkg
       ```

       The node runs for the user who is logged in. To run it as a system service that starts at boot, under its
       own `_oarbank` account, create an empty `/Library/Oarbank/etc/system` file before installing.
     </TabItem>
     <TabItem label="Linux" icon="linux">
       Put the join code where the package looks, then install the `.deb` (or the `.rpm` with `dnf`):

       ```sh
       sudo install -d /etc/oarbank
       echo 'OB1-…' | sudo tee /etc/oarbank/join-code >/dev/null
       sudo apt install ./oarbank-agent_2.7.0_amd64.deb
       ```

       The package creates an `oarbank` account and a systemd service whose jobs run in their own cgroups.
     </TabItem>
     <TabItem label="Windows" icon="seti:windows">
       Install the MSI with the join code, from an elevated prompt:

       ```powershell
       msiexec /i oarbank-agent-2.7.0-windows-x64.msi /qn JOINCODE=OB1-…
       ```

       The MSI installs the agent as a Windows service and a helper service that enforces each job's network
       allowlist. Use the `arm64` MSI on ARM64 PCs. Add `CONTAINERS=1` for modules that run containers (WSL
       containers; see [Requirements](/oarbank/operate/requirements)).
     </TabItem>
   </Tabs>

   The installer reads the join code and deletes it. The node enrolls with a key it generates and keeps, then
   installs its release, runs each module's doctor and golden jobs, and starts taking work.

   The coordinator's download holds only the coordinator: for the coordinator's computer to run jobs too, install the
   node package on it the same way, with a join code of its own. Every installer runs unattended, so you can also
   push it with your own SSH, MDM or configuration tool; the coordinator never connects to nodes itself.

5. **Add modules.** Oarbank ships no job module of its own: each job type is a module, delivered as a bundle. You
   install a bundle, approve what its sandbox may reach, and enable it. For the CLI examples below, use the [bundled CLI path](https://github.com/roeehrl/oarbank/blob/v2.7.0/docs/install.md#1-the-coordinator) or add its `bin` directory to your terminal's PATH:

   ```sh
   oarbank module install <bundle>.mfb
   oarbank module approve <name>@<version>
   oarbank module enable <name>@<version>
   ```

</Steps>

The full install guide, with system scope, updates, uninstalling and moving the coordinator, is
[docs/install.md](https://github.com/roeehrl/oarbank/blob/v2.7.0/docs/install.md) in the core's repository.

## Install the module SDK

To build your own job types, install the module SDK (`oarbank-sdk`, Apache-2.0). You need Python 3.12 or newer, on
macOS, Linux or Windows. It is not on PyPI yet; install it from its repository:

```sh
uv pip install "git+https://github.com/roeehrl/oarbank-sdk@v1.5.0"   # or: pip install "git+https://github.com/roeehrl/oarbank-sdk@v1.5.0"
oarbank-sdk --help
```

To work with the reference module and the examples, clone the repository instead and check the toy module with the
conformance kit:

```sh
git clone https://github.com/roeehrl/oarbank-sdk
cd oarbank-sdk
uv sync --group dev
uv run oarbank-sdk conform examples/toy   # must end with "0 failed"
```

The conformance kit runs your module's runner as each platform would, so you can test a module before you install it
on a fleet. [Build a module in a day](/oarbank/build/tutorial) builds a complete module step by step.
